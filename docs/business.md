# 业务目标与分析口径

平台围绕一笔贷款申请，整理其申请时可取得的资料和历史记录，估计数据集定义的还款困难事件，并解释模型响应、资料缺口和适用限制。当前部署面向本机历史回放与申请分析。

## 把业务问题变成数据问题

| 问题 | 本项目的口径 |
|---|---|
| 一行是什么 | 一笔当前贷款申请；历史子表可能一笔对应多行 |
| 预测什么 | 来源数据定义的 TARGET 事件，不补写未披露的 X／Y 期限 |
| 何时预测 | 当前申请时点；历史字段按相对日／月判断是否早于此时点 |
| 输出什么 | 概率估计、固定阈值分组、路径贡献、资料与来源说明 |
| 怎样使用 | 离线研究与本机案例分析；模拟复核记录不是实际授信决定 |
| 怎样衡量 | AUC／KS看排序，Brier看概率误差，阈值计数看误报漏报 |

数据分析的关键是保证统计对象与分母一致。例如“历史逾期月份占比”须明确按月份记录加权还是先按借款平均；两者不相同。“无符合条件历史”“未提供历史”“有记录但值缺失”和有效 0 也需要分别处理。

当前产品仅提供一条 71 项申请分析流程，历史资料是该流程的组成部分。早期 40 项模型和报告用于研究追溯，不能把其阈值或解释混入当前结论。

## 分析可以支持什么

项目可以用来讨论资料质量、历史信息增益、风险排序、阈值取舍与可追溯解释。它没有核验真实审批成本、放款收益、长期线上表现或新客迁移效果，不能据此建议直接拒贷。特征包含敏感或社会属性时，是否适用于真实授信还需要另行治理和检验；这里不作已通过主张。
